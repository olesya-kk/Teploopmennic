# Проверочные примеры

Эти примеры служат для демонстрации преподавателю и ручной проверки. Автоматические аналоги находятся в `tests/core_tests.cpp`; проверка работы окна — `tests/gui_tests.cpp`.

## 1. Аналитический тепловой баланс и противоток

В форме выбрать «Нагрев»: поток 1 холодный, поток 2 горячий. Для обеих сред — «Свойства вручную».

| Поле | Поток 1 (холодный) | Поток 2 (горячий) |
|---|---:|---:|
| Начальная температура, °C | 20 | 90 |
| Конечная температура, °C | 50 | 60 |
| Расход, кг/с | 2 | 2 |
| Допустимое ΔP, Па | 100000 | 100000 |
| Плотность, кг/м³ | 997 | 997 |
| Вязкость, Па·с | 0,001 | 0,001 |
| Теплоёмкость, Дж/(кг·К) | 4180 | 4180 |
| Теплопроводность, Вт/(м·К) | 0,6 | 0,6 |

Противоток; материал 12Х18Н10Т; загрязнения — вода среднего качества для обеих сторон; минимальный запас площади 10%; допуск K=0,00001; предел итераций 100.

Аналитический ответ:

- Qгор=2×4180×(90−60)=250800 Вт.
- Qхол=2×4180×(50−20)=250800 Вт.
- Концевые напоры: 90−50=40 и 60−20=40 К.
- Средний напор 40 К, поправка F=1.

Ожидается допустимый вариант, Q=250800 Вт, средний напор 40 К, запас площади не меньше 10%, каждое ΔP не выше 100000 Па. Геометрия и K являются результатом подбора, а не независимым аналитическим эталоном.

## 2. Прямоток на тех же исходных данных

Изменить только тип течения на «Прямоток».

Ответ: Q=250800 Вт; входной напор 90−20=70 К; выходной 60−50=10 К; LMTD=(70−10)/ln(70/10)=30,83390054 К. Поправка F=1. Вариант подбирается заново.

## 3. Несогласованный баланс и его исправление

В примере 1 изменить расход холодного потока с 2 до 1 кг/с.

Ответ: Qгор=250,8 кВт; Qхол=125,4 кВт. Расхождение |250,8−125,4|/250,8=50%, расчёт отклоняется до подбора.

Если остальные параметры заданы верно, восстановить расход холодного 2 кг/с. Нельзя исправлять баланс произвольной заменой известного параметра: выбирать нужно тот параметр, который допускается изменять по условиям задачи.

## 4. Справочные свойства из PDF

Открыть «Справочники и источники ПАХТ» → «Среды» и сверить:

| Среда, температура | ρ, кг/м³ | μ, Па·с | cp, Дж/(кг·К) | λ, Вт/(м·К) |
|---|---:|---:|---:|---:|
| Вода, 20 °C | 998,20 | 0,0010026 | 4181,7 | 0,5983 |
| Толуол, 20 °C | 866,9 | 0,000584 | 1691 | 0,134 |

Источник: печатные страницы PDF 109, 123–124, 127–128. В книге вязкость дана в мПа·с: при переносе в СИ она делится на 1000.

«Загрязнения»: вода среднего качества R=1/2380≈0,0004201680672 м²·К/Вт. Источник: с.136; пример выбора средней проводимости — с.80.

## 5. Независимые проверки отдельных формул

Это проверки ядра, не поля полной формы аппарата. Выполняются автоматически через `heat_tests`.

| Вход | Формула | Ожидаемый ответ |
|---|---|---:|
| w=2, d=0,02, ρ=1000, μ=0,001 | Re=w d ρ/μ | 40000 |
| cp=4200, μ=0,001, λ=0,6 | Pr=cp μ/λ | 7 |
| Nu=100, λ=0,6, d=0,02 | α=Nu λ/d | 3000 Вт/(м²·К) |
| α₁=1000, α₂=2000, δ=0,002, λст=20, Rf₁=0,0001, Rf₂=0,0002 | K=1/(1/α₁+Rf₁+δ/λст+Rf₂+1/α₂) | 526,3157895 Вт/(м²·К) |
| Напоры 60 и 30 К | LMTD=(60−30)/ln(60/30) | 43,28085123 К |
| Re=2488, Pr=Prст=5,976, εφ=0,6 | Nu=0,36 εφ Re^0,6 Pr^0,36 | ≈44,82 по PDF с.94 |
| Re=100, Pr=Prст=1, εφ=0,6 | Nu=0,56 εφ Re^0,5 Pr^0,36 | 3,36 |

В программном тесте для округлённого ответа PDF Nu≈44,82 допускается относительное отклонение 0,1%. Для аналитических ответов допуски существенно строже и указаны в `core_tests.cpp`.

## 6. Сохранение, загрузка и сравнение

1. Выполнить пример 1 — результат сохраняется автоматически.
2. Нажать «Назад», изменить течение на прямоток, выполнить пример 2.
3. Нажать «Назад» → «История и сравнение расчётов».
4. Найти оба расчёта по номеру/времени. Сравнить геометрию, площадь и запас в соседних строках.
5. Выбрать строку первого расчёта → «Загрузить выбранный расчёт». Откроется сохранённая спецификация.
6. Нажать «Назад»: исходные поля должны соответствовать выбранному расчёту, в частности тип течения — противоток.
7. Закрыть и снова открыть приложение: записи должны остаться. Двойной щелчок по строке также загружает расчёт.

## Запуск автоматических проверок

Из корня проекта:

```bash
cmake --build build -j 4
ctest --test-dir build --output-on-failure
```

Ожидается `100% tests passed`: два набора (ядро и интерфейс). Кроме численных примеров проверяются SQLite, миграция, невалидные данные, сходимость и одинаковый выбор при разном числе потоков OpenMP. Тесты используют отдельные временные базы и не меняют историю пользователя.
